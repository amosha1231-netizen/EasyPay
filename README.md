# EasyPay

מחלקים חשבון בין חברים לפי מה שכל אחד אכל, ושולחים לכל אחד כמה הוא מעביר.

## איך זה עובד

1. מי ששילם פותח חשבון חדש ומוסיף את מי שהיה.
2. מקליד את השורות מהחשבונית ומסמן מי חלק כל פריט (פריט בלי סימון מתחלק בין כולם). אפשר גם רק סכום כולל לחלוקה שווה.
3. בוחר טיפ, אם הוא לא נכלל בחשבונית. הטיפ מתחלק לפי כמה כל אחד הזמין.
4. בסיכום: שיתוף לקבוצה בוואטסאפ, או הודעה אישית לכל אחד עם הפירוט שלו ומספר ה-Bit / PayBox.
5. החברים פותחים את הקישור, בוחרים את השם שלהם ורואים בדיוק כמה להעביר ועל מה.

## למה אין שרת

כל החשבון נשמר בטלפון של מי שיצר אותו (`localStorage`), והקישור לחברים מכיל את החשבון עצמו בתוך הכתובת. אין מסד נתונים, אין התחברות, אין מסעדות ואין תפריטים, ולכן אין מה לתחזק: זה אתר סטטי. האפליקציה עובדת גם בלי אינטרנט ואפשר להוסיף אותה למסך הבית.

כל הסכומים מחושבים באגורות שלמות, כך שסכום החלקים תמיד שווה בדיוק לחשבון.

## קבצים

| קובץ | מה יש בו |
| --- | --- |
| `split.js` | כל החישובים: פענוח סכומים, חלוקה, טיפ, קידוד הקישור |
| `app.js` | המסכים |
| `style.css` | עיצוב (כולל מצב כהה) |
| `sw.js`, `manifest.webmanifest` | עבודה בלי אינטרנט והתקנה כאפליקציה |
| `tests/` | בדיקות ל-`split.js` |

## הרצה מקומית

```sh
npm test      # בדיקות
npm start     # http://localhost:3000
```

## פרסום

ה-workflow ב-`.github/workflows/ci.yml` מריץ את הבדיקות בכל PR ומפרסם ל-GitHub Pages בכל דחיפה ל-`main`. צריך להפעיל פעם אחת: Settings → Pages → Source: **GitHub Actions**.

כשמשנים קבצים, מעלים את `VERSION` ב-`sw.js` כדי שהטלפונים יקבלו את הגרסה החדשה.
